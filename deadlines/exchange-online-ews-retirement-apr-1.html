Apr 1, 2027 Phased switch-off: from Oct 2026

Exchange Online EWS is fully disabled from Apr 1, 2027 (phased switch-off from Oct 2026)

Microsoft says Exchange Web Services (EWS) in Exchange Online will be "fully and permanently disabled" starting April 1, 2027, with "no exceptions past April 2027." Before that, Microsoft is switching EWS off tenant by tenant from Oct 2026: tenants still on the default setting (Null) are changed to False, which blocks EWS for every app. Any app, script or service that still uses EWS needs to move to Microsoft Graph.

Who it's for: Microsoft 365 admins, and the people who look after a small business's Exchange Online mail, whose apps, scripts or services still use EWS.

Last updated Oct 22, 2026. Current dates: phased switch-off on (or soon after) Oct 1, 2026, tenant by tenant; full and permanent shutdown Apr 1, 2027. Microsoft updates its posts often, so re-check the sources.

Microsoft Learn's timeline says: "October 2026: EWS starts to be disabled globally for all organizations."

Plain-English summary

EWS (Exchange Web Services) is an older interface that apps and scripts use to connect to Exchange. Microsoft is retiring it in Exchange Online and calls Microsoft Graph "the long-term strategic platform for most Exchange Online integration scenarios."

What your tenant sees now depends on its EWSEnabled setting. Microsoft says a tenant still on Null is changed to False as the rollout reaches it, which blocks all EWS. A tenant set to True keeps EWS only for apps on its AppID allow list (EWSAllowedAppIDs): Microsoft says that after enforcement begins, "setting EWSEnabled=True without an AppID allow list effectively becomes a block-all configuration."

If you find out you still need EWS after the change, Microsoft says an admin can re-enable it, "But note that there will be a service interruption in this case." Either way, everything stops on Apr 1, 2027. EWS on on-premises Exchange is not being retired.

Free steps, from Microsoft's posts

  1. Review the EWS usage reports in the Microsoft 365 admin center to see which apps still call EWS. Microsoft also links scripts in "Notes From the Field: Finding and Remediating EWS App Usage Before Retirement".
  2. Read your tenant's setting (read-only), in Exchange Online PowerShell: Get-OrganizationConfig | Format-List EWSEnabled. Microsoft says an empty value is the default (Null).
  3. Read your current AppID allow list (read-only): Get-OrganizationConfig -RetrieveEwsOperationAccessPolicy | Format-List EwsAllowedAppIDs. Microsoft says the extra switch is required to return the list.
  4. If Microsoft filled in the list for you, check it. Microsoft says an auto-populated list is based on "the previous 60 days of usage", so "it may miss applications that run infrequently, and it may include apps you no longer want to have access." A list you create yourself is not overwritten.
  5. Sort every app into keep for now, move to Microsoft Graph, or retire. Microsoft's list of apps to keep can include its own clients: "This includes Microsoft first-party client apps such as Office, Power Query for Excel etc."
  6. Before anyone changes the list, note Microsoft's warnings: setting the property "writes the full list value", so existing App IDs are replaced unless included, and "Changes to this list can take up to 24 hours to take effect." Make changes only under your own change control.
  7. Ask each vendor whose app still uses EWS for its Graph date. Microsoft Learn says: "Work with your vendors to prioritize their migration from EWS."
  8. Check Microsoft Learn's parity-gap roadmap. Microsoft says: "If an EWS capability isn't listed in this roadmap table, don't plan on a corresponding Microsoft Graph or Exchange Admin API capability being available before EWS is fully disabled."

FAQ

When is EWS turned off in Exchange Online?

Microsoft's Exchange Team says: "Starting with April 1, 2027, EWS will be fully and permanently disabled" and "There will be no exceptions past April 2027." Before that, a phased switch-off rolls out tenant by tenant from Oct 2026.

What happens to tenants that never changed the EWSEnabled setting?

Microsoft says any tenant with EWSEnabled still set to Null on October 1, 2026, will see the value changed to False as the deployment rolls out, which blocks EWS for all applications in the tenant at that time.

We still need EWS for an app. What are the options?

Microsoft lists two choices until the final shutdown: set EWSEnabled to True and maintain an AppID Allow List (EWSAllowedAppIDs), or set EWSEnabled back to Null with Exchange Online PowerShell, which re-enables EWS without restrictions until the final deprecation. Microsoft's recommended path is to configure or validate the AppID allow list and then set EWSEnabled to True.

Does EWSEnabled set to True still allow every app?

No, once enforcement reaches the tenant. Microsoft says that after enforcement begins, setting EWSEnabled=True without an AppID allow list effectively becomes a block-all configuration.

Is EWS being retired for on-premises Exchange?

No. Microsoft says EWS is not being retired on-prem. Hybrid scenarios vary: on-prem mailboxes may continue using EWS, while cloud mailboxes must move to Microsoft Graph.

Can we get an extension past April 2027?

Microsoft's FAQ answers: "There will be no exceptions past April 2027."
