ProductCart sunset

ProductCart move-out to Shopify

NetSource-managed ProductCart hosting ends January 11, 2027 per the ProductCart sunset FAQ. This done-for-you scope maps your old public URLs to Shopify paths and delivers a cutover runbook. You keep DNS, hosting, email, and store build decisions; First Mover Projects never touches DNS, proxy, or CDN settings.

One primary domain per scope. Stores with more than 1,200 public ProductCart URLs are not a fit for this offer.

What you get

  • Public URL inventory (CSV) — Customer-visible ProductCart URLs found by a polite public crawl (GET only, robots.txt respected, at most one request per second), plus your sitemap and any URL list you send. No login or admin access.
  • 301 redirect map (CSV) — One row per old URL with a suggested new Shopify path, match confidence, and redirect outcome (see below).
  • Shopify-ready redirect import file — Rows Shopify’s redirect tool can accept, in its two-column import format.
  • Exceptions list — URLs that cannot use a native Shopify redirect, with options and risks written out for your team.
  • Merchant-run export checklist — What to export from your ProductCart control panel and how to store it (you run it).
  • Cutover and rollback runbook (PDF) — Ordered steps for whoever you assign, plus a launch-day redirect test list.

How each old URL is classified

Every URL in the redirect map is labeled with exactly one of three outcomes:

  1. Native Shopify redirect — Shopify's redirect import can take the old path. Shopify only applies a redirect when the old path shows a 404 on the new store, so the launch-day test list checks each one.
  2. Not native on Shopify (your decision) — Shopify's built-in redirects can't handle this URL (for example, paths that start with /shop). Any other approach, such as routing in front of Shopify, is your store's decision. First Mover Projects documents the options and risks and does not change your infrastructure. Shopify says Cloudflare proxy setups aren't supported by Shopify and can cause SSL certificate problems.
  3. Unmapped (our own label, not Shopify's) — We have no tested redirect row for that URL pattern in this scope.

The main gap is query-string URLs (for example viewPrd.asp?idproduct=123). Shopify's Help Center says URLs with query strings "might not work as expected" with URL redirects. We list them separately, never point them all at one page, and put each one on the launch-day test list. A row that fails the test is labeled "not native on Shopify (your decision)"; a pattern we can't map at all is labeled "Unmapped" (our own label).

ProductCart stores keep their catalog in different folders (for example /store/pc/, /eshop/pc/, /productcart/pc/ or /shop/pc/). Shopify's built-in redirects can't start from /shop paths, so if your store uses /shop/…, those URLs are marked "not native on Shopify (your decision)".

Shopify also says you can't redirect the fixed paths /products, /collections and /collections/all, or URLs beginning /apps, /application, /cart, /carts, /orders or /services.

NetSource’s FAQ notes that some fluctuation in search rankings is expected with any new site. We cannot promise rankings or traffic after the move.
